# 04. Новости

## Цель
Owner и editor создают, редактируют, публикуют (сразу или по расписанию) и удаляют новости на русском и казахском, с обложкой и фото из медиатеки; модель отдаёт готовые выборки для главной админки (08) и публичного сайта (11).

## Входит / не входит
- Входит:
  - Список `$a/news`: поиск по заголовку (RU и ҚАЗ), фильтр по статусу со счётчиками, пагинация, бейджи RU / ҚАЗ «нет перевода», предпросмотр, удаление с подтверждением.
  - Редактор `$a/news/new`, `$a/news/{id}/edit`: вкладки «Русский» / «Қазақша», заголовок, краткое описание, текст в WYSIWYG, «Скопировать с русского», обложка (одно фото) и «Фото к новости» (несколько, с порядком) через `partials/media-field.php`, вставка фото в текст, публикация: черновик / сразу / запланировать (дата+время, пояс из `config('timezone')`), адрес страницы (slug), автосохранение черновика, предпросмотр, удаление.
  - `App\Core\HtmlSanitizer` (белый список), `App\Core\Slug` (транслитерация RU+KK), `App\Core\Clock` (текущее время, подмена в тестах).
  - Провайдер медиа `news` в `app/media_usages.php` + FK `ON DELETE RESTRICT` (I-01, I-02, I-25).
  - Модель `App\Models\News` с сервисами для других фич: `published()`, `findPublishedBySlug()`, `latest(3)`, `translationStats()`, `renderBody()`.
  - Пункт меню «Новости» (owner и editor).
  - Доработка общего компонента `media-picker.js`: порядок в множественном поле (`data-sortable`) и программный вызов окна (`window.AdminMediaPicker.open`).
- Не входит:
  - Кнопка «Вставить видео» и видео в тексте (I-09) — фича 07; в 04 санитайзер вырезает `iframe`/`video`, в тулбаре кнопки видео нет.
  - Публичные страницы `/novosti`, `/novosti/{slug}`, кэш, OG — фича 11 (в 04 готовы только запросы модели). Ссылка «Посмотреть на сайте» в 04 ведёт на предпросмотр в админке.
  - Блок «Последние новости» на главной админки и счётчик «переведено N из M» — фича 08 (в 04 готовы `News::latest(3)`, `News::translationStats()`).
  - Переключатель интерфейса ҚАЗ, `kk.php` — фича 13 (интерфейс только русский; казахский — это контент).
  - Редиректы со старого slug, корзина/восстановление удалённых новостей, массовые действия.

## Изменения БД
Новый файл `migrations/005_news.sql`. Все даты — UTC, строка `Y-m-d H:i:s`.

```sql
CREATE TABLE news (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  slug           TEXT    NOT NULL UNIQUE,                 -- [a-z0-9-], 1..80
  title          TEXT    NOT NULL,                        -- RU (основной язык)
  excerpt        TEXT    NOT NULL DEFAULT '',
  body           TEXT    NOT NULL DEFAULT '',             -- только после HtmlSanitizer
  cover_media_id INTEGER NULL REFERENCES media(id) ON DELETE RESTRICT,
  status         TEXT    NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','published')),
  published_at   TEXT    NULL,                            -- UTC; NULL у черновика
  author_id      INTEGER NULL REFERENCES users(id) ON DELETE SET NULL,
  updated_by     INTEGER NULL REFERENCES users(id) ON DELETE SET NULL,
  version        INTEGER NOT NULL DEFAULT 1,              -- оптимистическая блокировка
  form_key       TEXT    NULL UNIQUE,                     -- ключ формы создания (идемпотентность)
  created_at     TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now')),
  updated_at     TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now'))
);
CREATE INDEX idx_news_status_pub ON news (status, published_at);
CREATE INDEX idx_news_cover ON news (cover_media_id);

CREATE TABLE news_translations (
  news_id    INTEGER NOT NULL REFERENCES news(id) ON DELETE CASCADE,
  lang       TEXT    NOT NULL CHECK (lang IN ('kk')),
  title      TEXT    NOT NULL DEFAULT '',
  excerpt    TEXT    NOT NULL DEFAULT '',
  body       TEXT    NOT NULL DEFAULT '',
  updated_at TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now')),
  PRIMARY KEY (news_id, lang)
);

CREATE TABLE news_media (
  news_id  INTEGER NOT NULL REFERENCES news(id) ON DELETE CASCADE,
  media_id INTEGER NOT NULL REFERENCES media(id) ON DELETE RESTRICT,
  place    TEXT    NOT NULL CHECK (place IN ('gallery','body')),
  sort     INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (news_id, place, media_id)
);
CREATE INDEX idx_news_media_media ON news_media (media_id);
```

- Русский текст — в `news` (основной язык), казахский — строка `news_translations` с `lang='kk'` (ARCHITECTURE §5). Строка kk создаётся/обновляется при каждом сохранении (пустые поля допустимы).
- `news_media.place='gallery'` — блок «Фото к новости» (порядок `sort` 0..N-1); `place='body'` — фото, вставленные в текст RU или KK (пересобирается из `<img data-media-id>` обоих тел при каждом сохранении, `sort` = порядок появления).
- Вычисляемое состояние (без cron): `draft` — `status='draft'`; `scheduled` — `status='published' AND published_at > :now`; `published` — `status='published' AND published_at <= :now`. `:now` — `Clock::nowUtc()`, передаётся параметром (не `strftime('now')` в SQL), чтобы тесты могли подменить время.

## Серверные компоненты
- **`App\Core\Clock`**: `nowUtc(): DateTimeImmutable` (UTC); `toLocal(string $utc): DateTimeImmutable`; `fromLocal(string $date, string $time): ?DateTimeImmutable` (строгий разбор `Y-m-d` + `H:i` в `config('timezone')`, перевод в UTC; несуществующая дата → `null`). При `APP_ENV=testing` время берётся из `storage/test_clock.json` (`{"now":"2026-11-25 04:00:00"}`, UTC), если файл есть.
- **`App\Core\Slug::make(string $text): string`**: нижний регистр, транслитерация, всё кроме `[a-z0-9]` → `-`, схлопывание и обрезка дефисов, длина ≤ 80 (обрезка по последнему дефису). Таблица: а a, б b, в v, г g, д d, е e, ё e, ж zh, з z, и i, й y, к k, л l, м m, н n, о o, п p, р r, с s, т t, у u, ф f, х kh, ц ts, ч ch, ш sh, щ shch, ъ —, ы y, ь —, э e, ю yu, я ya; казахские: ә a, ғ g, қ q, ң n, ө o, ұ u, ү u, һ h, і i. Пример: «Осенний утренник в старшей группе» → `osenniy-utrennik-v-starshey-gruppe`; «Конкурс рисунков «Менің Отаным»» → `konkurs-risunkov-menin-otanym`. Пустой результат → `novost`.
- **`News::uniqueSlug(string $base, ?int $exceptId): string`** — `base`, затем `base-2`, `base-3`…
- **`App\Core\HtmlSanitizer::clean(string $html): string`** на `DOMDocument` (UTF-8, `LIBXML_NONET`, без внешних сущностей):
  - Разрешены теги: `p, br, strong, em, h2, ul, ol, li, a, img`. Замены: `b→strong`, `i→em`, `div→p`, `h1/h3–h6→h2`.
  - Удаляются вместе с содержимым: `script, style, iframe, object, embed, video, audio, form, input, textarea, select, button, svg, math, template, noscript, head, title, meta, link`, комментарии.
  - Прочие теги (`span`, `font`, `u`, `table`…) разворачиваются: тег убран, текст остаётся.
  - Атрибуты: все удаляются, кроме `a[href]` и `img[data-media-id]`. `href` после `trim` и удаления управляющих символов допускается только со схемой `http:`, `https:`, `mailto:` (без учёта регистра); иначе (`javascript:`, `data:`, относительные, пустые) `<a>` разворачивается в текст. Для `http/https` сервер ставит `target="_blank" rel="noopener noreferrer"`; для `mailto` — без `target`.
  - `img`: остаётся только `data-media-id` (целое > 0, запись `media` типа `image` существует), иначе тег удаляется; `src`, `alt`, `style`, `on*` удаляются всегда.
  - Пустые `<p></p>`/`<p><br></p>` в конце удаляются; тело без текста и без `img` → `''`.
  - Идемпотентность: `clean(clean(x)) === clean(x)`.
- **`News::renderBody(string $html, string $size = 'medium'): string`** — заменяет каждый `<img data-media-id="N">` на `media_picture(Media::find(N), $size)`; отсутствующий файл → ничего (без битой картинки). Используется предпросмотром и фичей 11 (I-30).
- **`News::bodyForEditor(string $html): string`** — для редактора добавляет `src` (thumb/medium JPEG) и `alt` к `img[data-media-id]`.
- **`App\Media\NewsUsageProvider`** (`key()='news'`): один запрос по `news.cover_media_id` и `news_media` для всех id; по одному элементу на пару (файл, новость): `label` = `Новость «<title>» (обложка, фото, в тексте)` — перечислены только реальные роли; `url` = `admin_url('/news/{id}/edit')`. Регистрируется в `app/media_usages.php`.
- **Модель `App\Models\News`** (все запросы подготовленные):
  - `list(string $q, string $state, int $page): array{items,total,page,pages,per_page}` — `$state ∈ all|published|draft|scheduled`; поиск `php_lower(title) LIKE` или `php_lower(kk.title) LIKE` (как в `Media::list`: `%`/`_` буквально, ≤ 100 символов); сортировка `COALESCE(published_at, updated_at) DESC, id DESC`; в строке — `state`, имя автора, cover-строка `media`, `kk_ready`.
  - `counts(string $q): array{all,published,draft,scheduled}` — счётчики фильтров с тем же `q`.
  - `find(int $id): ?array` (с kk, `cover`, `photos` по `sort`).
  - `save(?int $id, array $data, int $userId, ?int $expectedVersion): array` — в `Database::immediate`: проверка `version` (иначе `NewsConflictException`), запись `news`, kk, пересборка `news_media`, `version+1`.
  - `delete(int $id): ?array`.
  - `state(array $row, ?DateTimeImmutable $now = null): string` — единственная функция вычисления состояния (I-29).
  - `isTranslated(array $row): bool` — ключи строки `title, body, kk_title, kk_body`. KK заголовок непуст, и (KK текст непуст или RU текст пуст), и версия не является копией русской: совпадение И заголовка, И текста с русскими (после `trim`) = «нет перевода». Достаточно, чтобы отличался заголовок или текст. SQL-вариант тех же условий (`News::TRANSLATED_SQL`) используется списком, `published()` и `translationStats()`.
  - **Для фичи 11 (I-03):** `published(int $page = 1, int $perPage = 10): array{items,total,page,pages}` — только `status='published' AND published_at <= :now`, сортировка `published_at DESC, id DESC`; `findPublishedBySlug(string $slug): ?array` — то же условие, иначе `null`.
  - **Для фичи 08 (I-04):** `latest(int $limit = 3): array` — последние по `COALESCE(published_at, updated_at) DESC` во всех состояниях, у каждой `state`, `title`, `edit_url`, дата (локальная).
  - **Для 08/13 (I-10):** `translationStats(): array{total:int, translated:int}` — из тех же данных, что бейджи.
- `Media::registerLower()` выносится в `Database::registerLower()` (публичный); `Media` и `News` используют его.
- `Requirements`: новый обязательный пункт `dom` (расширение DOM, нужно санитайзеру), статус `fail` при отсутствии. Тесты 01 на число требований обновить (12 → 13).
- Журнал (`Audit::log`): `news.create`, `news.update`, `news.publish`, `news.schedule`, `news.unpublish`, `news.delete`. Автосохранение пишет только `news.create` при создании (обновления автосохранением не журналируются).

## Правила сохранения
- Поля формы: `title_ru`, `excerpt_ru`, `body_ru`, `title_kk`, `excerpt_kk`, `body_kk`, `cover_media_id`, `photos[]`, `publish_mode` (`draft|now|later`), `publish_date` (`Y-m-d`), `publish_time` (`H:i`), `slug`, `slug_auto` (`1` — адрес не правили вручную), `version`, `form_key`, `intent` (`submit|draft`).
- Валидация (ошибка → 422, форма с введёнными данными, ошибки у полей, ничего не сохранено):
  - `title_ru`: обязателен всегда (после `trim`), ≤ 120 символов. `title_kk`: ≤ 120.
  - `excerpt_*`: ≤ 300 символов, только текст (HTML сохраняется как текст, вывод через `e()`).
  - `body_*`: после санитайзера ≤ 200 000 байт.
  - `cover_media_id`: существующее фото (`type='image'`) или пусто; `photos[]`: существующие фото, без дублей, ≤ `news.max_photos` (50). Несуществующий id → ошибка у поля «Фото удалено из медиатеки — выберите другое».
  - `publish_mode=later`: дата и время обязательны, корректны и строго позже `Clock::nowUtc()` (на момент сохранения); иначе ошибка «Укажите будущие дату и время».
  - `slug`: после `Slug::make`; если `slug_auto=1` или поле пустое — генерируется из `title_ru` и делается уникальным суффиксом; если введён вручную и занят другой новостью — ошибка «Этот адрес уже занят новостью «…»».
- Статус по кнопке:
  - `intent=draft` (кнопка «Сохранить черновик») → `status='draft'`, `published_at=NULL`.
  - `intent=submit` + `publish_mode=draft` → черновик (у опубликованной — «снять с публикации»).
  - `intent=submit` + `now` → `status='published'`; `published_at` = сейчас, если новость не была опубликована (`state ≠ published`); у уже опубликованной дата не меняется.
  - `intent=submit` + `later` → `status='published'`, `published_at` = введённое время в UTC.
- Конфликт: `version` из формы ≠ версии в БД → 409, форма с введёнными данными и баннер `news-conflict`; ничего не сохранено.
- Идемпотентность создания: `form_key` (случайные 32 hex, создаётся при открытии `$a/news/new`). Повторный POST/автосохранение с тем же `form_key` обновляет уже созданную запись, а не создаёт вторую.

## Редактор текста (решение)
Свой минимальный редактор `public/assets/admin/editor.js` (~300 строк, без сборки, без CDN, без внешних зависимостей) на `contenteditable` + `document.execCommand` (`bold`, `italic`, `formatBlock h2/p`, `insertUnorderedList`, `createLink`/`unlink`, вставка `img`).
Обоснование: в макете 6 кнопок; готовые лёгкие библиотеки (Pell, ~1 КБ) — та же обёртка над `execCommand` без пользы, а крупные (Squire, Quill, TinyMCE) — 50–400 КБ, свои форматы и лицензии, их надо вендорить и обновлять. Граница безопасности — серверный `HtmlSanitizer`, поэтому клиенту не нужна сложная очистка. Источник данных — скрытая `<textarea name="body_ru|body_kk">`, редактор синхронизирует `innerHTML` при каждом вводе и перед отправкой. Вставка из буфера — только `text/plain`: пустая строка → новый абзац, перенос → `<br>` (форматирование из Word/сайтов не переносится, мусорных стилей нет). Горячие клавиши браузера (Ctrl+B/I/Z) работают.

## Связи с другими фичами
- **I-01** (владелец 04): обложка, фото к новости и фото в тексте → провайдер `news`; карточка файла в медиатеке показывает «Новость «X» (обложка, фото, в тексте)» со ссылкой на редактор; значок «Используется» в сетке.
- **I-02** (03): фото, используемое новостью, нельзя удалить (кнопка `disabled`, список мест); FK `ON DELETE RESTRICT` в `news.cover_media_id` и `news_media.media_id` — прямой `DELETE` тоже отказывает.
- **I-03** (04, 11): в 04 — `News::published()` и `findPublishedBySlug()` возвращают только `status='published' AND published_at <= now`; черновик и будущая запланированная не возвращаются; после наступления даты (подмена `Clock`) — возвращаются. Публичные страницы — тест в 11.
- **I-04** (08): в 04 готов `News::latest(3)` с верным `state`; блок на главной — тест в 08.
- **I-09** (04, 07): в 04 видео в тексте нет: кнопки нет, `iframe`/`video` вырезаются санитайзером. Вставку видео и заглушку удалённого видео делает 07 (расширяет белый список `HtmlSanitizer` и `renderBody`).
- **I-10** (04, 05, 08, 13): бейджи `news-badge-kk`, `news-tab-kk-state` и `News::translationStats()` используют одно правило `isTranslated()` (заполнено И отличается от русского); заполнение/очистка/копирование KK сразу меняет бейдж и статистику.
- **I-11** (10, 11, 13): предпросмотр KK уже подставляет русский текст с «Аударма жоқ» — в 11 используется та же логика.
- **I-14**: editor имеет полный доступ к новостям (создание, публикация, удаление любых новостей) — по ARCHITECTURE §8.
- **I-15**: создание/изменение/публикация/снятие/удаление пишутся в `audit_log` с автором.
- **I-17**: `005_news.sql` применяется на установленном сайте при первом запросе.
- **I-23**: пункт «Новости» для owner и editor; `crawl.spec.js` проходит список, фильтры, пагинацию, редактор, предпросмотр без 4xx/5xx и ошибок консоли.
- **I-24**: сохранение/удаление после таймаута → вход, не сохранено; неверный CSRF → 400; автосохранение после таймаута → 401 JSON, на странице сообщение, текст не потерян; 500 нет.
- **I-25**: провайдер `news` в реестре; одно фото в обложке одной новости и в фото другой → два места в карточке.
- **I-26**: фото, загруженное во вкладке «Загрузить» окна обложки/фото/тулбара, сразу в медиатеке и выбрано; форма хранит id.
- **I-27**: миниатюры списка, превью и предпросмотр выводят фото только через `media_picture()`; смена alt в медиатеке сразу видна в предпросмотре.
- Новые строки в `docs/INTEGRATION.md`: **I-28** (освобождение фото при удалении/изменении новости), **I-29** (единое вычисление статуса и часовой пояс), **I-30** (HTML из редактора только через санитайзер и `renderBody`).

## Критерии приёмки
- [ ] Миграция `005_news.sql` создаёт `news`, `news_translations`, `news_media` с FK и индексами из спеки; применяется на установленном сайте один раз.
- [ ] Owner и editor видят пункт «Новости» и могут создать, отредактировать, опубликовать, запланировать, снять с публикации и удалить новость; без входа любой URL `$a/news*` ведёт на вход.
- [ ] Список: поиск по RU и KK заголовку без учёта регистра (кириллица и казахские буквы), 4 фильтра со счётчиками, равными реальному числу строк в каждом фильтре при текущем `q`; 20 на страницу; `?page=999` → последняя, `?status=xxx` → «Все».
- [ ] Бейдж «ҚАЗ — нет перевода» показан ровно у новостей, где `isTranslated()=false`; `News::translationStats()` совпадает с числом зелёных бейджей.
- [ ] Новость с `published_at` в будущем имеет статус «Запланирована» и не входит в `News::published()`; после подмены `Clock` на время ≥ `published_at` — «Опубликована» и входит в `published()`, без cron и без сохранения.
- [ ] Время, введённое как 25.11.2026 09:00 при `timezone=Asia/Almaty`, хранится как `2026-11-25 04:00:00` UTC и показывается как `25.11.2026, 09:00`.
- [ ] `Slug::make` даёт `osenniy-utrennik-v-starshey-gruppe` и `konkurs-risunkov-menin-otanym` для примеров спеки; одинаковые заголовки → `x`, `x-2`, `x-3`; ручной занятый адрес → ошибка у поля, ничего не сохранено.
- [ ] `HtmlSanitizer`: `<script>`, `on*`, `style`, `iframe`, `javascript:`/`data:` ссылки, `src` у `img` удаляются; `b/i` → `strong/em`; внешние ссылки получают `target="_blank" rel="noopener noreferrer"`; повторная очистка ничего не меняет. В БД `news.body`/`news_translations.body` нет ни одного запрещённого тега/атрибута после сохранения любого ввода.
- [ ] Обложка, фото к новости (в выбранном порядке, перестановка кнопками и перетаскиванием) и фото в тексте сохраняются; каждое отображается в карточке медиатеки как использование этой новости; такое фото нельзя удалить ни через UI, ни прямым `DELETE` (FK); после удаления новости или отвязки фото — можно.
- [ ] Автосохранение черновика: изменение → запрос через 5 с бездействия; повторная отправка/двойной клик/параллельное автосохранение новой новости создают ровно одну запись (`form_key`); опубликованная новость автосохранением не меняется.
- [ ] Две вкладки: сохранение устаревшей версии → 409 и баннер, данные в БД от первой вкладки не перезаписаны.
- [ ] Предпросмотр (POST) показывает несохранённые правки и не меняет БД (число строк и `updated_at` прежние).
- [ ] `News::latest(3)`, `News::published()`, `News::findPublishedBySlug()`, `News::translationStats()` существуют, покрыты PHPUnit и не дают N+1 (не более 3 запросов на вызов).
- [ ] В админке нет кнопки «Вставить видео»; ни одна кнопка не ведёт на 404/500.
- [ ] Все строки интерфейса — через `t()`; все testid из таблицы присутствуют; `php -l`, PHPUnit, Playwright зелёные; в консоли браузера нет ошибок.

## Вопросы
1. Фото в тексте (кнопка «Вставить фото» в макете, I-01 «в тексте новости») — включено в 04 как `<img data-media-id>` + `news_media.place='body'`. По умолчанию: делаем.
2. Казахский текст в макете — простая textarea; принято: тот же WYSIWYG, чтобы форматирование RU/KK совпадало. По умолчанию: редактор в обеих вкладках.
3. Редактор может удалять и снимать с публикации чужие новости? ARCHITECTURE §8 ограничений не задаёт. По умолчанию: да, без ограничений по автору.
4. Перетаскивание файла прямо на поле «Обложка» (в макете «или перетащите сюда») — компонент 03 этого не умеет. По умолчанию: только через окно выбора (вкладка «Загрузить» принимает перетаскивание); подпись «или перетащите сюда» не выводим.
5. «Скопировать с русского»: РЕШЕНО иначе, чем по умолчанию — казахская версия считается переведённой, только если заполнена И отличается от русской (заголовком или текстом); скопированная без изменений = «нет перевода» (бейджи, `translationStats()`, I-10).
6. Ссылка «Посмотреть на сайте» в списке до фичи 11 ведёт на предпросмотр в админке; в 11 для опубликованных заменить на `/novosti/{slug}`.
7. Новое обязательное требование `dom` в установщике: уже установленные сайты без DOM (крайне редко) получат 500 в редакторе. По умолчанию: при отсутствии `DOMDocument` `NewsController` отвечает 503 с текстом `error.extension_missing` вместо 500.
