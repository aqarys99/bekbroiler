# 02. Вход и пользователи

## Цель
Сотрудник садика входит в админку по логину и паролю (с защитой от подбора и «Запомнить меня»), видит макет админки с меню и шапкой и безопасно выходит. Ответственный за сайт (`owner`) ведёт список сотрудников: добавляет, меняет данные и роль, блокирует, сбрасывает пароль. Каждый может сменить свой пароль в профиле.

## Входит / не входит
- Входит:
  - Экран входа по `docs/design/Login.dc.html`: логин, пароль с кнопкой «показать», «Запомнить меня на этом устройстве», подсказка «Забыли пароль?», подсказка о блокировке.
  - Выход (POST с CSRF), регенерация ID сессии при входе, смена CSRF-токена при входе, таймаут 2 часа бездействия.
  - Защита от подбора: 5 неудачных попыток по паре (IP, логин) за 15 минут → блок на 15 минут; 20 неудачных с одного IP (любые логины) → блок IP на 15 минут.
  - «Запомнить меня» на 30 дней: токен selector + validator, в БД только SHA-256 хэш validator, ротация при каждом использовании.
  - Охрана всех маршрутов админки (`Guard`): гость → вход; нет роли → 403; POST без верного CSRF → 400.
  - Макет админки `layouts/admin.php` по `docs/design/Main.dc.html`: левое меню, шапка с хлебными крошками, «Открыть сайт», карточка пользователя (ссылка на профиль), «Выйти», всплывающее сообщение (flash).
  - Главная `/admin`: приветствие (полный дашборд — фича 08).
  - Роли `owner`/`editor`, проверка роли на сервере в каждом запросе (роль читается из БД, а не из сессии).
  - Раздел «Пользователи» (только `owner`): список, добавить, изменить (имя, логин, роль), заблокировать/разблокировать, сбросить пароль. Нельзя заблокировать или понизить самого себя и последнего активного `owner`.
  - Профиль: свои имя/логин/роль (только просмотр) и смена своего пароля с вводом текущего.
  - Немедленное действие блокировки, сброса пароля и смены пароля на уже открытые сессии и «запомненные» устройства (`users.auth_version`).
  - `audit_log` для входов/выходов и всех действий с пользователями (I-15).
  - Локальный шрифт Inter (woff2) в `public/assets/admin/fonts/` (долг из 01).
  - Страница ошибки 400 (`errors/400.php`), E2E для `error-403` (долг из 01).
  - `tests/e2e/crawl.spec.js` — обход всех ссылок и кнопок админки под `owner` и `editor` (долг из 01).

- Не входит:

  - Восстановление пароля по e-mail/SMS — нет (сброс делает `owner`, см. подсказку на экране входа).

## Изменения БД
Новый файл `migrations/002_auth.sql` (001 не менять):

```sql
ALTER TABLE users ADD COLUMN auth_version INTEGER NOT NULL DEFAULT 1;

CREATE TABLE remember_tokens (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  selector     TEXT    NOT NULL UNIQUE,      -- 24 hex (random_bytes(12)), ищется по нему
  token_hash   TEXT    NOT NULL,             -- hash('sha256', validator), 64 hex
  expires_at   TEXT    NOT NULL,             -- UTC, created_at + 30 дней
  created_at   TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now')),
  last_used_at TEXT    NULL
);
CREATE INDEX idx_remember_tokens_user ON remember_tokens (user_id);

CREATE INDEX idx_login_attempts_ip_login ON login_attempts (ip, login, created_at);
```

- `users.auth_version` — увеличивается на 1 при: сбросе пароля owner'ом, смене своего пароля, блокировке. Сессия хранит версию на момент входа; несовпадение → сессия завершается при следующем запросе.
- `login_attempts` хранит **только неудачные** попытки (`login` — нормализованный: `trim` + `mb_strtolower`, обрезан до 100 символов). Записи старше 24 ч удаляются при каждой неудачной попытке.
- Время — UTC `Y-m-d H:i:s` (соглашение 01). Показ — `Asia/Almaty`, формат `дд.мм.гггг чч:мм`.

### Auth
- `Auth::attempt(string $login, string $password, bool $remember, string $ip): AuthResult` — порядок:
  1. Нормализовать логин. `LoginThrottle::lockedFor($ip, $login)` > 0 → `locked` (минуты, округление вверх), попытка **не** записывается, `password_verify` не вызывается.
  2. Найти пользователя по логину (`COLLATE NOCASE`). Нет пользователя → `password_verify` против фиктивного хэша (одинаковое время ответа) → неудача.
  3. Неверный пароль → `LoginThrottle::fail($ip, $login)`; `Audit::log(null, 'login_failed', 'user', $userIdOrNull)`; если эта попытка довела счётчик до блокировки → дополнительно `Audit::log(null, 'login_locked', 'user', $userIdOrNull)` и результат `locked` (15 мин); иначе `invalid`.
  4. Пароль верен, `is_active = 0` → `blocked` (попытка не записывается, ошибка «Учётная запись заблокирована…»).
  5. Успех: `password_needs_rehash` → перехэшировать; `LoginThrottle::clear($ip, $login)`; `Session::regenerate()`; новый `_csrf`; в сессию `user_id`, `auth_version`, `_last_activity = time()`; `users.last_login_at = now`; `Audit::log($id, 'login', 'user', $id)`; `$remember` → `RememberMe::issue($id)`.
- `Auth::user(): ?array` — один раз за запрос: сессия с `user_id` → проверить таймаут (`time() - _last_activity > 7200` → `Session::destroy()`, флаг `timedOut`), затем загрузить пользователя из БД; нет пользователя / `is_active=0` / `auth_version` не совпал → `Session::destroy()` + `RememberMe::forgetCurrent()`, `null`. Если сессии нет → `RememberMe::consume()` (см. ниже). Успех → `_last_activity = time()`.
- `Auth::logout()` — `Audit::log($id, 'logout', 'user', $id)`, `RememberMe::forgetCurrent()`, `Session::destroy()`.
- `Auth::bumpVersion(int $userId)` — `auth_version + 1` и удалить все `remember_tokens` пользователя. Если это текущий пользователь (смена своего пароля) — обновить версию в своей сессии и `Session::regenerate()`.
- IP — только `$_SERVER['REMOTE_ADDR']` (`X-Forwarded-For` не используется: подделывается).

### LoginThrottle
- `fail($ip, $login)`: вставить строку; удалить строки старше 24 ч.
- `lockedFor($ip, $login): int` (секунды до разблокировки, 0 — свободно). Для пары (ip, login): `T` = время последней неудачи; если неудач в `[T−15 мин, T]` ≥ 5 и `now < T+15 мин` → `T+15 мин − now`. То же для IP по всем логинам с порогом 20. Возвращается максимум. Пока блок действует, неудачи не пишутся, поэтому `T` — момент 5-й (20-й) неудачи.
- `clear($ip, $login)`: удалить строки пары (IP-счётчик по другим логинам не трогается).
- Константы: `MAX_PER_LOGIN = 5`, `MAX_PER_IP = 20`, `WINDOW = 900`, `LOCK = 900`.

### RememberMe
- `issue(int $userId)`: `selector = bin2hex(random_bytes(12))`, `validator = bin2hex(random_bytes(32))`; в БД `hash('sha256', validator)`, `expires_at = now + 30 дней`; cookie `sadik_remember = selector:validator`, `expires` +30 дней, `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, путь как у сессии. У пользователя > 10 токенов → удалить самые старые. Истёкшие токены всех пользователей удаляются здесь же.
- `consume(): ?int`: формат cookie `^[0-9a-f]{24}:[0-9a-f]{64}$`, иначе удалить cookie → `null`. Нет строки по `selector` или истёк → удалить cookie/строку → `null`. Сравнение с текущим `token_hash` и с `prev_hash` (см. ниже); не совпал ни с одним → кража: удалить **все** токены пользователя, `Auth::bumpVersion($userId)` (завершает его открытые сессии), cookie → `null`. Пользователь заблокирован → удалить его токены → `null`. Успех: ротация условным `UPDATE … SET token_hash=new, prev_hash=old, rotated_at=now WHERE id=? AND token_hash=old` (cookie перевыпускается; `expires_at` не продлевается); если 0 строк — параллельный запрос уже ротировал, проверяется окно `prev_hash`, вход как в `Auth::attempt` шаг 5 без пароля, `Audit::log($id, 'login_remember', 'user', $id)`.
- Окно прошлого токена (миграция `003_remember_rotation.sql`: `prev_hash`, `rotated_at`): validator, чей хэш равен `prev_hash`, принимается **10 с** после `rotated_at` (восстановление вкладок, параллельные GET); вход без ротации и без перевыпуска cookie, аудит `login_remember_prev`. Позже 10 с — кража (см. выше).
- `issue()` при новом входе с галочкой удаляет прежний токен этого устройства (по cookie запроса).
- `forgetCurrent()`: удалить строку по selector из cookie и сам cookie.

### Guard
`Guard::wrap(array|Closure $handler, string $role = 'editor'): Closure` — используется в `routes.php` для всех `{a}/*`, кроме `login`:
1. `Auth::user()` = null: GET/HEAD → `302 {a}/login?next=<путь+query>`; POST → `302 {a}/login`; если причина — таймаут, `Flash::set('info','auth.timeout')`.
2. `$role === 'owner'` и роль пользователя `editor` → `HttpException(403)`.
3. POST и `!csrf_verify($_POST['_csrf'] ?? null)` → `HttpException(400)`.
4. Вызвать обработчик, передав `$params`; текущий пользователь — `Auth::user()`.
- `next` принимается только если начинается с `{a}` (с `base_path`) и не содержит `//`, `\`, `:` до `?`, `\r`, `\n`; иначе `{a}`.

## Критерии приёмки
- [ ] Миграция `002_auth.sql` применяется на сайте, установленном в 01, ровно один раз; у существующего владельца `auth_version = 1`; `remember_tokens` создана с `ON DELETE CASCADE`.
- [ ] Все маршруты `{a}/*`, кроме `GET/POST {a}/login`, под гостем дают `302` на вход (проверяется PHPUnit-перебором `Router::routes()`, ни один маршрут не пропущен).
- [ ] Вход меняет значение cookie `sadik_sid` и `_csrf`; cookie сессии `HttpOnly`, `SameSite=Lax`, без `Expires` (до закрытия браузера).
- [ ] Через 7201 с бездействия сессия недействительна; через 7100 с — действительна и отсчёт сбрасывается.
- [ ] 5 неудач пары (IP, логин) за 15 мин → 6-я попытка (даже с верным паролем) → 429 без `password_verify`; через 15 мин после 5-й — вход работает. 20 неудач с одного IP по разным логинам → блок IP. Успешный вход удаляет записи пары.
- [ ] Ответ на неизвестный логин и на неверный пароль известного логина — одинаковый текст и код; время ответа отличается не более чем на 50% (оба вызывают `password_verify`).
- [ ] В `remember_tokens` нет validator в открытом виде (64 hex `token_hash` ≠ части cookie); каждое использование меняет cookie и `token_hash`; подмена validator удаляет все токены пользователя.
- [ ] Блокировка, сброс пароля и смена своего пароля: другие сессии пользователя завершаются на следующем запросе, `remember_tokens` пользователя — 0 строк.
- [ ] Ни одним запросом (UI или прямой POST, в т. ч. два параллельных) нельзя получить 0 активных `owner`; нельзя заблокировать себя или понизить свою роль.
- [ ] Editor: 403 на все GET/POST `{a}/users*`; пункта «Пользователи» нет в HTML; owner, пониженный до editor, получает 403 со следующего запроса.
- [ ] Каждое действие из раздела «Аудит» даёт ровно одну строку `audit_log` с правильными `action`, `user_id`, `entity_id`; ошибки валидации и сохранение без изменений — ни одной.
- [ ] Пароли нигде не возвращаются в HTML и не пишутся в лог; хэши — `password_hash(PASSWORD_DEFAULT)`.
- [ ] Все POST админки без верного `_csrf` → 400 (форма входа — 400 с `login-error`), данные не меняются.
- [ ] Инициалы, имена, логины, `site_name` выводятся через `e()` (XSS-тест с `<script>` в имени и названии).
- [ ] `@font-face` Inter 400/500/600/700 из `public/assets/admin/fonts/` отдаётся 200; на всех экранах 02 нет запросов к внешним доменам; в `ru.php` есть все ключи раздела «Тексты», в `admin-views/` нет русских строк вне `t()`.
- [ ] На экранах 02 нет кнопок RU/ҚАЗ и пунктов меню несуществующих разделов; ни одного `href="#"` и `TODO`.
- [ ] `crawl.spec.js` под owner и editor: каждая внутренняя ссылка админки (кроме выхода) отвечает < 400 (для editor — кроме ожидаемых 403 из списка `OWNER_ONLY_URLS`), нет ошибок консоли, каждый `a, button, input, select, textarea` на каждой странице имеет `data-testid`, каждая кнопка `type="button"` нажимается без ошибок.
- [ ] Ширина 360px: на экранах входа, главной, списка пользователей, форм и профиля нет горизонтальной прокрутки (`scrollWidth ≤ clientWidth`).

## Вопросы
1. **Переключатель RU/ҚАЗ.** По умолчанию: скрыт полностью (на входе и в шапке) до фичи 13 — неактивная кнопка противоречит правилу «работает или её нет».
2. **Пункты меню будущих разделов.** По умолчанию: скрыты; каждая фича добавляет пункт в `app/admin_menu.php` (I-23).
3. **Блокировка по IP.** «5 попыток по IP и логину» буквально по IP заблокировал бы весь садик за одним NAT из-за одного сотрудника, а только по логину позволял бы злоумышленнику запирать владельца. По умолчанию: 5 на пару (IP, логин) + 20 на IP по всем логинам.
4. **Сброс пароля.** По умолчанию: owner сам вводит новый пароль (видит его через «глаз») и сообщает сотруднику; генерации пароля и обязательной смены при первом входе нет (не в ROADMAP).
5. **«Запомнить меня»** по умолчанию снят (в дизайне отмечен как пример); срок 30 дней без продления, до 10 устройств на пользователя.
6. **Удаление пользователей** не делаем — только блокировка (ARCHITECTURE §8, сохраняет авторство).
7. **Заглушка `/`.** Текст «Админка будет доступна после фичи 02» становится неправдой. По умолчанию: «Сайт скоро откроется.»; тесты 01 обновить.
8. **Выкладка `deploy.yml`** на приложение (обещано «после фичи 02» в спеке 01) — по умолчанию не в этой фиче, решить отдельно владельцу проекта.
9. **Страница 403/400** ведёт «На главную» (`/`), а не в админку — оставляем как в 01 (общий шаблон ошибок без БД).
