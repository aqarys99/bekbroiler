# Спецификации фич

Каждую спеку пишет агент `planner` в файл `docs/specs/NN-название.md` по шаблону ниже. Builders строят **только** то, что в спеке; тесты пишутся **по таблицам** спеки.

---

```markdown
# NN. Название фичи

## Цель
Одно-два предложения: что пользователь сможет делать.

## Входит / не входит
- Входит: …
- Не входит (будет в фиче NN): …

## Изменения БД
Новый файл миграции `migrations/NNN_*.sql`: таблицы, поля, индексы.

## Маршруты
| Метод | URL | Контроллер::метод | Роль | Что делает | Ответ |
|---|---|---|---|---|---|

## Элементы интерфейса (каждая кнопка)
| testid | Экран | Элемент | Действие пользователя | Ожидаемый результат | Ошибки/пограничные случаи |
|---|---|---|---|---|---|
| news-publish | Редактор новости | Кнопка «Опубликовать» | Нажать при заполненном заголовке | Новость сохраняется со статусом published, редирект в список, тост «Новость опубликована» | Пустой заголовок → ошибка у поля, ничего не сохраняется |

## Связи с другими фичами
Ссылки на строки `docs/INTEGRATION.md` (I-xx) + новые строки, которые эта фича добавляет.

## Тексты интерфейса
Ключи для `app/lang/ru.php`: `news.publish => 'Опубликовать'`, …

## Критерии приёмки
- [ ] …

## План тестов
- PHPUnit: …
- E2E: по одному тесту на каждую строку «Элементы интерфейса» + каждую связь I-xx.
```
