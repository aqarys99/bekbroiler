# Выкладка на хостинг (PS.kz и аналоги)

Apache + `.htaccess`, без Composer и Node на хостинге. Сайт — один набор файлов; данные живут отдельно (см. «Где лежат данные»).

## Требования к хостингу

| Что | Минимум |
|---|---|
| PHP | 8.1 или новее (панель PS.kz: «Настройки PHP» -> версия 8.1+) |
| Расширения | `pdo_sqlite`, `gd` **с поддержкой WebP**, `fileinfo`, `mbstring`, `dom`, `zip` (для архива резервной копии; без него скачивается только база) |
| Лимиты PHP | `upload_max_filesize` >= 25M, `post_max_size` >= 30M, `memory_limit` >= 128M (лучше 256M), `max_execution_time` >= 60 |
| Диск | 2-5 ГБ для начала; видео лучше держать на YouTube |
| Apache | `mod_rewrite`, `mod_headers` (желательно), разрешён `.htaccess` |
| HTTPS | сертификат Let's Encrypt включить в панели PS.kz до установки; сайт отдаёт HSTS только при HTTPS |

Лимиты меняются в панели («Настройки PHP») или файлом `.user.ini` в `public/` (для варианта Б — в корне сайта):
`upload_max_filesize = 25M`, `post_max_size = 30M`, `memory_limit = 256M`.
Установщик (`install.php`) сам проверит расширения и покажет, чего не хватает.

## Вариант А. Корень сайта = `public/` (рекомендуется)

Наружу видно только `public/`, остальное недоступно из интернета в принципе.

1. В панели PS.kz откройте «Сайты» -> ваш домен -> «Корневая папка» и создайте папку вне `public_html`, например `sadik/`.
2. Загрузите проект в `sadik/` (FTP, файловый менеджер или GitHub Actions, см. ниже; `server-dir: sadik/`).
3. Смените корневую папку домена на `sadik/public` (в панели PS.kz это поле «Корневая папка»; если смена недоступна — попросите поддержку или сделайте `public_html` символической ссылкой на `sadik/public` по SSH).
4. Откройте `https://домен/install.php` (см. «Первый запуск»).

`base_path` = `''`.

## Вариант Б. Корень сайта = папка сайта (`public_html/`)

Если корень домена сменить нельзя.

1. Загрузите весь проект в `public_html/` (в `server-dir` укажите `public_html/`).
2. Корневой `.htaccess` закрывает `app`, `storage`, `config`, `migrations`, `admin-views`, `bin`, `themes` (кроме отдачи ресурсов через PHP), точечные файлы и служебные расширения, а остальные запросы переписывает в `public/`. Прямой адрес `/public/...` перенаправляется на путь без `public`. Дополнительно в каждой закрытой папке лежит свой `.htaccess` с `Require all denied` (работает и без `mod_rewrite`).
3. **Обязательно** проверьте список ниже («Проверка `.htaccess`»): `/storage/database.sqlite` и `/config/config.php` должны отвечать 403 или 404.
4. Откройте `https://домен/install.php`.

Сайт в подпапке (`https://домен/sadik/`): установщик сам определит `base_path` (`/sadik`) и запишет его в `config/config.php`.

## Выкладка через GitHub Actions (по желанию)

Workflow `.github/workflows/deploy.yml` запускается **только вручную** (Actions -> «Deploy to PS.kz» -> Run workflow). По умолчанию включён «пробный запуск» (ничего не меняет на сервере) — снимите галочку для настоящей выкладки.

- Секреты (Settings -> Secrets and variables -> Actions): `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD` (данные FTP из письма PS.kz или панели).
- Переменная `FTP_SERVER_DIR`: `public_html/` (вариант Б) или `sadik/` (вариант А). Слеш в конце обязателен.
- В сборку не попадают `tests`, `docs`, `.claude`, `.github`, `node_modules`, `vendor`, базы `*.sqlite`, содержимое `public/uploads`, `config/config.php`.
- На сервере **не перезаписываются** `storage/` (база, копии, кэш, логи), `config/config.php`, `public/uploads/`. Первая выкладка кладёт только код.
- Передача по FTPS (шифрованный FTP). Если сервер не принимает FTPS, включите его в панели PS.kz; обычный FTP не используем.

## Первый запуск (`install.php`)

1. Откройте `https://домен/install.php`. Страница проверит PHP, расширения, права на папки. Красные пункты нужно устранить (панель хостинга или поддержка), жёлтые — желательно.
2. Введите данные первого пользователя (ответственный за сайт, роль owner) и название сада.
3. Установщик создаст базу `storage/database.sqlite`, применит миграции, запишет `config/config.php` и `storage/install.lock`. После этого `install.php` отвечает 403.
4. Зайдите в `https://домен/admin`, заполните «Настройки».
5. Проверьте права: `storage/`, `config/`, `public/uploads/` доступны на запись (755/775).

Объём тарифа для «Занято X из Y»: «Настройки» -> поле лимита диска, либо ключ `disk_quota_mb` в `config/config.php` (если не задан — берётся `disk_total_space`). Например, тариф 5 ГБ: `'disk_quota_mb' => 5120,`. Само по себе значение не блокирует загрузку, а только показывает заполнение.

## Где лежат данные

Всё, что нужно сохранить при переезде или поломке:

| Путь | Что это |
|---|---|
| `storage/database.sqlite` | вся база: новости, документы, настройки, пользователи (и файлы `-wal`, `-shm` рядом) |
| `public/uploads/` | фото, видео, документы |
| `config/config.php` | настройки сервера (`base_path`, `admin_path`, `disk_quota_mb` и др.) |
| `storage/backups/` | автокопии базы (раз в сутки, 14 последних) |
| `storage/logs/` | журнал ошибок |

## Резервные копии

«Система» -> «Резервные копии» (только owner):
- «Скачать архив» — один zip: `database.sqlite`, `public/uploads/...`, `config/config.php`, `README.txt`. **Архив содержит все данные сайта (в том числе хэши паролей) и настройки сервера — храните его в надёжном месте.** Раз в месяц и перед обновлением сохраняйте архив на свой компьютер.
- Автокопия базы создаётся сама при первом заходе в админку за день (без cron) в `storage/backups/`, хранятся 14 последних. В них нет фото и документов.
- Если на хостинге нет расширения `zip`, кнопка скачает только базу.

### Восстановление из архива

Из админки восстановить нельзя (намеренно: опасно). Вручную, по FTP или в файловом менеджере PS.kz:

1. Разверните чистую копию сайта (варианты А/Б выше) **без** запуска `install.php`, либо возьмите существующую.
2. Распакуйте архив на своём компьютере.
3. Закачайте `database.sqlite` в `storage/database.sqlite` (заменив файл). Файлы `storage/database.sqlite-wal` и `-shm`, если есть, удалите.
4. Закачайте папку `public/uploads/` из архива в `public/uploads/` (с заменой).
5. Закачайте `config/config.php` в `config/config.php`. Если переезжаете на другой домен/подпапку, отредактируйте `base_path`.
6. Создайте пустой файл `storage/install.lock` (если нет), чтобы `install.php` был закрыт.
7. Очистите `storage/cache/` (удалите файлы внутри) и откройте `https://домен/admin`. Войдите прежним логином.

Восстановление только базы из автокопии: скачайте `db-ГГГГММДД-ЧЧММСС.sqlite` в разделе «Резервные копии» (или возьмите из `storage/backups/`), положите как `storage/database.sqlite`, удалив `-wal`/`-shm`, очистите `storage/cache/`.

## Обновление сайта новой версией

1. Сделайте и сохраните архив («Резервные копии» -> «Скачать архив»).
2. Выложите новую версию: GitHub Actions (см. выше) или вручную загрузите файлы **кроме** `storage/`, `config/config.php`, `public/uploads/`.
3. Новые файлы `migrations/NNN_*.sql` применятся сами при первом запросе; по SSH можно выполнить `php bin/migrate.php`.
4. Откройте админку, проверьте главную и сайт. При проблеме верните прежние файлы кода и, если менялась база, восстановите её из копии.

## Повторная установка

Только вручную: удалите `storage/install.lock`, `storage/database.sqlite` (и `-wal`, `-shm`), `config/config.php`. **Все данные будут потеряны.**

## Видео и cron (необязательно)

Если на хостинге есть `ffmpeg`, загруженные MP4 можно сжимать по cron: `php /путь/к/сайту/bin/process-videos.php` раз в 5-10 минут. Без ffmpeg ничего настраивать не нужно.

## Права на файлы

`storage/`, `config/`, `public/uploads/` должны быть доступны на запись (755/775). `config.php`, `database.sqlite`, `install.lock` создаются с правами 0640; если хостинг запускает PHP от другого пользователя и чтение невозможно, используется 0644 (запись в лог).

## Проверка `.htaccess` вручную

Должны вернуть 403 или 404:

- `/storage/database.sqlite`
- `/config/config.php`
- `/app/helpers.php`
- `/migrations/001_core.sql`
- `/.git/HEAD`
- `/uploads/test.php` (положите тестовый файл и удалите после проверки)

Должны работать:

- `/install.php` (до установки — форма, после — 403 «Установка уже выполнена»)
- `/`
- `/admin`
- `/assets/admin/admin.css`

## Загрузка фото (медиатека)

- Лимит файла = минимум из `media.max_upload_mb` (по умолчанию 20), `upload_max_filesize` и `post_max_size`. Если на хостинге стоит 2 МБ, поднимите `upload_max_filesize` и `post_max_size` до 25M и 30M (панель хостинга или `.user.ini`); иначе фото с телефона без сжатия не пройдут.
- Обязательно: расширения PHP `gd` с поддержкой JPEG и WebP (`imagewebp`) и `fileinfo`; без GD+WebP установка не проходит, а загрузка отвечает 503 `image_unsupported`. `memory_limit` не меньше 128M (лучше 256M): фото 12 Мп без сжатия в браузере требует около 110 МБ.
- Фото HEIC без сжатия в браузере принимаются только при установленном `Imagick` с поддержкой HEIC; иначе сервер отвечает понятной ошибкой, браузер iPhone обычно сам конвертирует снимок.
- Оригиналы не хранятся: на диске остаётся 6 файлов на фото (3 размера × WebP и JPEG).
- Объём тарифа для «Занято X из Y»: ключ `disk_quota_mb` в `config/config.php` (если не задан — берётся `disk_total_space`).
