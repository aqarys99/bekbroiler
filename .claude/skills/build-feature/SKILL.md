# /build-feature <NN | next>

Ты — оркестратор. Сам код не пишешь: раздаёшь задачи агентам, держишь короткий учёт и решаешь, когда фича готова.

## Экономия контекста (обязательно)
- В начале читай ТОЛЬКО `docs/PROGRESS.md`, строку фичи в `docs/ROADMAP.md` и `CLAUDE.md`. Не открывай код и логи сам — это делают агенты.
- Агентам давай короткие задачи со ссылками на файлы, а не пересказ содержимого.
- От агентов принимай только их короткие отчёты; не проси «покажи весь вывод».
- Всё, что нужно помнить между сессиями, — в `docs/PROGRESS.md`, а не в разговоре.

## Шаги
0. Определи фичу (для `next` — первая `⬜` в ROADMAP, у которой все зависимости `✅`). Поставь ей `🟦` в ROADMAP. Запомни базовый коммит: `git rev-parse HEAD`.
1. **План** → агент `planner`: «Напиши спеку для фичи NN из ROADMAP». Если в ответе есть «Вопросы» без безопасного решения по умолчанию — спроси пользователя; иначе продолжай.
2. **Сборка** → `backend-builder`: «Реализуй серверную часть по docs/specs/NN-*.md». Затем `frontend-builder`: «Сделай экраны по docs/specs/NN-*.md и docs/design/». (Последовательно: фронт опирается на маршруты бэка.)
3. **Тесты** → `test-writer`: «Напиши тесты по docs/specs/NN-*.md и связям I-xx этой фичи».
4. **Прогон** → `test-runner`.
5. **Цикл исправлений** (до 3 кругов): если КРАСНЫЙ — отдай каждую ошибку нужному builder'у (сервер → backend, интерфейс → frontend, ошибка в самом тесте → test-writer) одним сообщением со списком из отчёта → снова `test-runner`.
6. **Ревью** → `reviewer` с базовым коммитом. НА ДОРАБОТКУ → блокеры нужным агентам → `test-runner` → снова `reviewer` (до 3 кругов).
7. Не сошлось за 3+3 круга — остановись, запиши состояние в PROGRESS и спроси пользователя.
8. **Фиксация**:
   - Добавь в `docs/PROGRESS.md` блок фичи по шаблону ниже (≤ 15 строк).
   - ROADMAP: `✅`.
   - Регрессия: `test-runner` по ВСЕМУ проекту ещё раз — старые фичи не должны сломаться.
   - `git add -A && git commit -m "feat(NN): <название>"` и `git push -u origin <текущая ветка>`.
9. Ответь пользователю 3–5 строками: что готово, сколько тестов, что осталось. Предложи `/compact` перед следующей фичей.

## Шаблон блока в docs/PROGRESS.md
```
## NN. Название — ✅ YYYY-MM-DD
- Сделано: 1–3 строки
- Ключевые файлы: app/…, admin-views/…, migrations/NNN_…
- Решения: важные выборы, которые нельзя забыть
- Тесты: PHPUnit N, E2E N (testid M из M, связи I-xx…)
- Известные ограничения / долги: …
```
