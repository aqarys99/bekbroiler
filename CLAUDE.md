# Проект: сайт детского сада + админка

Коробочный продукт: одна админка, сменные темы сайта, каждый садик получает свою копию.
Сейчас строим **админку и бэкенд**; публичный сайт — тема `themes/solnyshko` (по `index.html`).

## Главные документы (читать перед работой)
- `docs/ARCHITECTURE.md` — архитектура, таблицы БД, структура папок, безопасность.
- `docs/ROADMAP.md` — список фич по порядку и их статус.
- `docs/INTEGRATION.md` — как фичи связаны между собой (новости ↔ фото ↔ документы ↔ главная). **Любое изменение сверять с этой матрицей.**
- `docs/specs/NN-*.md` — спецификация каждой фичи (пишет агент `planner`).
- `docs/design/*.dc.html` — дизайн экранов админки. Брать оттуда разметку, цвета, тексты, размеры. Цвета: фон `#F4F5F7`, текст `#1C2230`, акцент `#1F5BD8`, рамки `#E2E5EA`, зелёный `#17703A/#E6F4EA`, оранжевый `#9A4D00/#FDF0E1`, красный `#B42318/#FDECEA`. Шрифт Inter.

## Стек и ограничения
- PHP 8.1+ (локально 8.3), SQLite через PDO, без фреймворков, без Composer-зависимостей в продакшене.
- Composer только для dev (PHPUnit). Node только для dev (Playwright).
- Должно работать на обычном казахстанском хостинге (Apache + .htaccess, без ffmpeg, без Node).
- Интерфейс админки на русском, все строки через `t('key')` из `app/lang/ru.php` (казахский `kk.php` позже).
- Контент — двуязычный по структуре (`*_translations` или поля `_kk`), см. ARCHITECTURE §5.

## Команды
- Запуск локально: `php -S 127.0.0.1:8080 -t public public/index.php`
- Проверка синтаксиса: `find app public -name '*.php' -print0 | xargs -0 -n1 php -l`
- Юнит/интеграционные тесты: `vendor/bin/phpunit`
- E2E (каждая кнопка): `npx playwright test --trace off`
  - `@playwright/test` закреплён на **1.63.0** (совпадает с установленным браузером). Не запускать `playwright install`.

## Правила кода
- Только подготовленные запросы PDO. Весь вывод через `e()`. CSRF-токен в каждой POST-форме.
- Каждый интерактивный элемент админки имеет `data-testid` (формат `раздел-действие`, напр. `news-publish`), его же используют тесты.
- Загрузки: проверка `finfo`, белый список, случайное имя, перекодирование фото (см. ARCHITECTURE §6, §9).
- Миграции — только новыми файлами в `migrations/`, старые не менять.
- Никаких заглушек «TODO» в сданной фиче: кнопка либо работает, либо её нет.

## Как работаем (агенты)
Фичи строятся циклом через скилл `/build-feature <номер или название>`:
planner (Opus) → backend-builder + frontend-builder (Sonnet) → test-writer (Sonnet) → test-runner (Haiku) → reviewer (Opus) → исправления → повтор, пока всё не зелёное.
Подробно: `.claude/skills/build-feature/SKILL.md`.

## Готово (Definition of Done) для каждой фичи
1. Все пункты «Критерии приёмки» в спеке выполнены.
2. Каждая строка таблицы «Элементы интерфейса» спеки покрыта E2E-тестом, тест зелёный.
3. Каждая связь фичи из `docs/INTEGRATION.md` покрыта тестом, тест зелёный.
4. `php -l`, PHPUnit и Playwright — без ошибок; в консоли браузера нет ошибок; нет ответов 500.
5. reviewer вернул `ВЕРДИКТ: ПРИНЯТО`.
6. Статус в `docs/ROADMAP.md` обновлён.
